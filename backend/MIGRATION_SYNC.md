# Database Migration Sync Guide

## Issue Resolution (Jan 31, 2026)

A migration conflict was identified and resolved. This document helps team members sync their local databases.

## What Happened

1. **Duplicate Migration**: There were two migration files numbered `0008`:
   - `0008_inquiry_table.sql` (manually created)

3. **Resolution**:

## For Team Members: How to Sync Your Local Database

### Option 1: Fresh Database (Recommended for Development)

If you don't have critical local data:

```bash
cd backend

# Delete your local database
rm -rf .wrangler/state/v3/d1

# Pull latest code
git pull

# Apply all migrations from scratch
yarn db:migrate:apply
```

### Option 2: Manual Sync (If You Have Local Data)

If you need to preserve your local data:

```bash
cd backend

# 1. Check which migrations are pending
yarn db:migrate:list

# 2. If you see migration errors about duplicate columns, manually add missing column:
wrangler d1 execute DB --local --command "ALTER TABLE booking ADD COLUMN refund_amount_cents INTEGER;"

# 3. Apply the booking_cancellation_otp table if missing:
wrangler d1 execute DB --local --file drizzle/migrations/0010_booking_cancellation_otp.sql

# 4. Register the migrations as applied:
wrangler d1 execute DB --local --command "INSERT INTO d1_migrations (name, applied_at) VALUES ('0010_booking_cancellation_otp.sql', datetime('now')), ('0011_booking_cancellation_metadata.sql', datetime('now'));"

# 5. Verify no pending migrations:
yarn db:migrate:list
```

### Option 3: Update Migration Tracking Only

If you already manually added the columns:

```bash
cd backend

# Register migrations as applied without running them
wrangler d1 execute DB --local --command "INSERT OR IGNORE INTO d1_migrations (name, applied_at) VALUES ('0010_booking_cancellation_otp.sql', datetime('now')), ('0011_booking_cancellation_metadata.sql', datetime('now'));"

# Verify
yarn db:migrate:list
```

## Verification

After syncing, verify your database is correct:

```bash
# Should return: ✅ No migrations to apply!
yarn db:migrate:list

# Check if refund_amount_cents column exists
wrangler d1 execute DB --local --command "PRAGMA table_info(booking);" | grep refund_amount_cents

# Check if booking_cancellation_otp table exists
wrangler d1 execute DB --local --command "SELECT name FROM sqlite_master WHERE type='table' AND name='booking_cancellation_otp';"
```

## Production Deployment

**IMPORTANT**: Before deploying to production, ensure:

1. The production database has all migrations applied
2. Test the migration on a staging environment first
3. Back up the production database

To apply to production:

```bash
cd backend

# List pending migrations in production
yarn db:migrate:list:prod

# Apply migrations to production (requires confirmation)
yarn db:migrate:apply:prod
```

## Questions or Issues?

If you encounter any migration errors:

1. Check the error message carefully
2. Try Option 1 (Fresh Database) if possible
3. Contact the team lead if Option 2 doesn't work
4. Don't force migrations or modify migration files manually

## Best Practices Going Forward

1. **Always** use `yarn db:generate` to generate migrations
2. **Never** manually edit migration files after they're committed
3. **Always** test migrations locally before committing
4. **Never** delete or rename committed migration files
5. Use descriptive names for migrations when possible
